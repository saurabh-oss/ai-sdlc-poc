The problem

AI assistance moved faster than the controls around it.

Teams adopted coding assistants in weeks. The review, audit and compliance machinery around them is still manual. This project builds the missing half and makes it observable.

Before the commit

Guardrails the assistant reads

A checked-in rules file tells Claude Code and Cursor what they may not do: no hardcoded credentials, no string-built SQL, no disabled TLS, no edits to protected infrastructure files. The rules load before every session, so the constraints shape the output instead of being discovered in review.

At the commit

Gates that actually block

A secret pushed on a branch fails the build at stage two and increments a counter you can see on a dashboard. The policy gate rejects commit messages that break convention and edits to files developers should not touch. Nothing depends on a reviewer noticing.

After the commit

An audit trail by default

Generated code carries an AI-assisted marker. The pipeline publishes contribution ratios, policy violations, review scores and coverage as time series. When someone asks how much of this was written by a model and who checked it, the answer is a query.

Architecture

One workstation, seven services, one feedback loop.

Code flows left to right. Telemetry flows back. Every box is a container started by a single compose file, and every arrow is a real connection you can watch in the logs.

The pipeline

Six gates between a push and a green build.

Four of them can stop the build outright. The last one is why any of this is measurable: it publishes what happened so the dashboards have something to draw.

01

Checkout

Pulls the pushed branch and prepares the reports directory that every later stage writes into.

Always passes
02

Secret scan

Runs detect-secrets and diffs the result against a committed baseline, so only genuinely new credentials fail. A finding fails the build and increments secret_leak_attempts_total.

Blocks
03

Static analysis

Semgrep against the Python and OWASP Top Ten rule packs. Findings are parsed by severity and published as sast_findings_high and sast_findings_medium.

Blocks
04

AI policy check

The project's own rule engine. It enforces Conventional Commits, rejects edits to protected infrastructure files, flags credential-shaped literals, and warns on print statements left in production paths.

Blocks
05

Tests and coverage

Runs pytest with coverage and a JUnit report. The suite covers the task API and the auth module, including validation, conflict and authentication failure paths.

Blocks
06

Push metrics

Ships coverage, SAST counts, policy violations, review score and pipeline duration to the Prometheus Pushgateway, where Grafana picks them up within one scrape interval.

Guardrails

The rules the assistants read before they write.

Checked into the repository so they version with the code. The policy gate enforces the subset a machine can verify.

Secrets and data

  • No hardcoded keys, tokens or passwords — environment variables only
  • Environment files never committed, only a placeholder template
  • Personal data masked in every log statement
  • Parameterised queries; never SQL built by string concatenation

Code standards

  • Type hints on every function signature
  • Google-style docstrings on public functions and classes
  • Functions capped at 50 lines, files at 300
  • No bare exception handlers, no leftover print statements

Architecture

  • Layered flow: api to service to repository to models
  • New dependencies need a declared rationale
  • Endpoints need validation, auth and error handling
  • Schema changes require a migration, never a direct edit

Boundaries

  • Infrastructure and monitoring files are off limits to assistants
  • No disabling security scans or pipeline gates
  • No force pushes to the main or develop branches
  • Generated code carries an AI-assisted marker for the audit trail

The stack

Everything is a container except the editor.

One compose file brings the whole environment up. Ports below are the defaults; they are easy to remap when something else on the machine already holds one.

Run it

Two commands to the full environment.

Python 3.11 to 3.13, Docker Desktop, and roughly three gigabytes for images on the first pull.

Bring the stack up
# install dependencies and start every service
poetry install
docker compose up -d

# seed the boards with demo telemetry
python scripts/seed_demo_data.py --loop
Run the gates locally
# the same checks the pipeline runs
make test-cov
make secret-scan
make policy-check

# the AI review agent, needs an API key
make review
